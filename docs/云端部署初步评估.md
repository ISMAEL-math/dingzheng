# 钉正云端部署初步评估

评估日期：2026-10-22。范围：检查当前项目的部署条件与改造路线；本次没有部署服务器或修改业务代码。用户已确认：给少量朋友使用，每个人的数据分开。建议初版采用邀请注册，不开放公开注册。

## 判断

项目已有 Node HTTP 服务和同源前端，可以部署到常驻服务器。真正影响使用体验的工作是云端持久化、跨设备数据一致性与后台任务。应分别定义“网址可以访问”和“学习数据、批改任务都在云端”两个目标。

## 当前实现与影响

| 当前实现 | 代码位置 | 对云端版的影响 |
| --- | --- | --- |
| Node 服务同时提供网页和 API；监听 127.0.0.1，支持 PORT | server.mjs | 同机反向代理可保持回环监听；容器部署需配置可从容器外访问的监听地址 |
| 网页调用相对路径 /api | public/app.js | 可保留前后端同源部署 |
| 学习状态整体存入 IndexedDB；PDF 与批改照片也存在浏览器 | public/app.js 的 save、load、saveGradingPhotos | 不同设备不会自动同步；原 localhost 数据也不会自动出现在新域名 |
| profile 仅为浏览器中的显示信息，没有登录会话 | public/app.js、server.mjs | 私人云端访问也需要访问控制；多人使用另需账户与数据隔离 |
| API 可使用服务器环境变量中的模型密钥，没有应用级身份校验 | server.mjs | 公网部署前必须保护所有 API，防止未授权调用服务器配置的服务 |
| 网页执行照片识别、逐题检索、工具调用和批改调度 | public/app.js 的 gradePhotos、runGradingAgent | 关闭网页或移动端挂起后，不能保证任务继续；当前恢复依赖浏览器保存的进度 |
| MinerU 请求在单次 HTTP 请求内轮询，整体超时 12 分钟；原始 PDF 上限 200 MB | server.mjs | 需验证代理超时、上传限制与内存占用；可靠版宜改成可持久化后台任务 |
| 向量由浏览器传入，服务端仅缓存最近的检索索引 | rag-index.mjs | 这不是持久化云端知识库；资料、片段和向量需迁移并建立按用户或工作区的访问控制 |

## 建议路线

### 第一步：开发环境部署验证

目标是验证部署链路与手机使用体验，仅供开发验证。保留现有模型服务，配置 HTTPS 与访问控制，保护全部业务 API，验证流式响应、上传和 PDF 资源。浏览器存储阶段各设备的数据暂不互通，不能将该阶段当作已完成的朋友试用版。

优先考虑单个常驻 Node 服务，便于承接现有长请求。可容器化以统一依赖和启动方式。暂不绑定具体云厂商；选型前确认主要访问地区、服务器到模型及 PDF 服务的连通性、上传与流量成本。

### 第二步：少量朋友可用的云端初版

- 邀请注册与独立账户从第一版开始实现。建议采用服务端会话与 HttpOnly、Secure Cookie，并处理跨站请求伪造防护；账户密码使用成熟的密码哈希方案，提供会话撤销与账户停用。
- 服务端保存错题、聊天、知识库资料元数据及批改记录。
- 照片和 PDF 存入受保护的持久化文件目录或对象存储，以文件 ID 关联记录。
- 每条学习记录、资料片段、文件、向量和后台任务都关联所属用户。服务端从登录会话取得用户身份；读取、修改、下载、导出和检索都校验归属，不能相信前端提交的 user_id，也不能仅靠隐藏界面隔离。
- 单实例少量用户可评估 SQLite；多实例或较多并发写入时评估 PostgreSQL。数据库与文件必须有独立备份及恢复验证。
- 以服务端数据为准，按实体或变更保存；用版本号检测多设备覆盖，避免直接互相覆盖当前整个 state。
- 将识别、检索和批改调度迁至后台，保存每一步进度与失败状态；网页查看进度并提交取消或重试。
- 单实例可先用数据库任务表和 worker，无需起步就引入独立消息队列。任务要支持重启恢复、避免重复写入，并记录模型请求的不确定完成状态。
- 为每用户及全站设置任务并发和调用限制，防止一位用户的批量作业长期占用全部处理能力。
- 模型费用方案待确定：可让朋友各自配置 API Key，或由管理员提供统一额度并按人限额。每用户凭证仅供其任务使用；服务端持久化密钥时加密保存，主密钥与数据备份分开管理，不回传完整凭证。
- 旧数据通过 localhost 版本导出备份，再在云端登录后导入；检查 PDF 原文件与照片能否完整迁移，不能假设当前 JSON 导出涵盖全部 IndexedDB 文件。

### 第三步：根据真实试用反馈扩展

先邀请少量朋友验证，再按数据量和排队情况决定是否增加数据库服务、对象存储或 worker 实例。初版不要求公开注册、收费订阅、团队共享资料或复杂角色体系；新增共享功能时另行设计授权规则。

## ChatGPT 套餐接入与云端部署

需要区分两种场景：

1. 自己在远程 VM 上运行开源应用：官方提供 self-hosted VM 流程，包括本地完成 OAuth、安全转移指定会话凭证、为 VM 保留独立主机 ID，并由 VM 负责后续刷新。
2. 向他人提供远程托管应用：不能直接假定本地开源授权流程适用。官方要求通过其渠道申请此类接入，需确认开放资格。

OAuth 的 127.0.0.1 回调会到达浏览器所在设备，不会自动到达云服务器。不能只把本机地址替换成网站域名，就认为已经完成官方远程登录适配。

建议把云端数据与任务改造和 ChatGPT 套餐接入分别验证。云端初版可继续使用已有模型 API，让两项工作的进度互不依赖。

本项目已确定属于向少量其他用户提供托管应用的方向，不能把“个人自托管 VM”流程自动等同于朋友各自网页登录的接入方案。ChatGPT 套餐接入需先确认该使用方式的资格与授权流程；各人的凭证与用量应独立关联，不共用管理员的登录凭证。

## 验收重点

- 未登录无法调用模型、读取资料或下载私有文件。
- 使用两个真实测试账户验证：账户 A 无法通过替换记录、文件、任务或资料 ID 读取、修改、下载、取消或导出账户 B 的内容；知识库检索也不返回他人片段。管理员界面不默认展示朋友的学习内容。
- 新域名的数据导入可恢复错题、照片和资料关联；检查原始 PDF 完整性。
- 两个设备可查看同一条记录，同时编辑不会静默覆盖。
- 离开网页后批改继续；服务重启后可恢复任务，不重复收录结果。
- 聊天流式显示、手机上传照片、PDF 解析在实际部署环境可用。
- 数据库和文件备份能在新实例恢复；密钥不进入前端资源、日志或备份导出。
